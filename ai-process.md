## 2. Примеры промптов и результатов

### 2.1. Выбор идеи
**Промпт:**
> «Предложи 5 идей учебного fullstack-проекта с React и Supabase, чтобы покрыть
> требования: 3+ экрана, авторизация, CRUD, 3 связанные таблицы БД, 2+ интеграции.
> Для каждой — кратко плюсы и сложность.»

**Результат:** выбрана идея «HabitFlow — трекер привычек» (компактно, но покрывает все требования).

### 2.2. Проектирование БД
**Промпт:**
> «Спроектируй PostgreSQL-схему для трекера привычек: пользователи, привычки
> (с днями недели), отметки выполнения по дням. Нужны: ограничения целостности,
> индексы, триггеры, Row Level Security (пользователь видит только свои данные).
> Выдай готовый идемпотентный SQL для Supabase.»

**Результат:** сгенерирован `001_init.sql` (таблицы `profiles`, `habits`, `check_ins`,
CHECK-ограничения, уникальность отметок, триггер `handle_new_user`, RLS-политики).

### 2.3. Генерация кода API
**Промпт:**
> «Напиши на TypeScript модуль `api.ts` для работы с Supabase: fetchHabits,
> createHabit, updateHabit, deleteHabit, addCheckIn, removeCheckIn. Ошибки PostgREST
> переводи в человекочитаемые русские сообщения по кодам (23505, 42501, PGRST301...).»

**Результат:** сгенерирован `src/lib/api.ts` с классом `AppError` и маппингом ошибок.

### 2.4. Написание тестов
**Промпт:**
> «Напиши unit-тесты для api.ts с моком supabase. Проверь: маппинг строк в Habit,
> что user_id не передаётся при createHabit, что addCheckIn глотает код 23505.»

**Результат:** сгенерирован `src/lib/api.test.ts`.

### 2.5. Отладка (реальный кейс)
**Проблема:** падал `npm run build` — ошибка в JSX.
**Промпт с ошибкой:**
> «Вот текст ошибки tsc: "Cannot find name 'clamped'" в ProgressBar.tsx. Что не так?»

**Решение:** в JSX-стиле `style={{ width: `${clamped}%` }}` вложенный шаблон
`${...}` внутри JSX-выражения — конфликт. Исправлено на `width: clamped + '%'`.

## 3. Возникшие проблемы и решения

| Проблема | Причина | Решение |
|----------|---------|---------|
| `npm ci` падал | версия Node < 22.22.2 | добавили `.nvmrc`, Node 22+ |
| Сборка не видела `VITE_SUPABASE_URL` | секреты не заданы в CI | добавили секреты GitHub Actions |
| Google-вход не работал | неверный redirect URI | исправили на `.../auth/v1/callback` |
| Отметку можно было ставить дважды | не было unique constraint | добавили `unique (habit_id, date_key)` |

## 4. Выводы и рекомендации

- AI ускоряет рутину (SQL-схемы, boilerplate, тесты), но результат нужно **проверять**:
  код и схему БД я ревьюил вручную и правил (например, убирал лишний индекс).
- Промпты должны быть **конкретными**: что сделать, на каком стеке, какие ограничения.
- AI хорошо справляется с объяснением ошибок компилятора — это сэкономило часы отладки.
- Для продакшена AI-код нужно прогонять через линтер/тесты/security-аудит — что и сделано в CI.
